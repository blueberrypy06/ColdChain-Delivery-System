# ColdChain-Delivery-System
# 동적 우선순위 및 다중 화물차 배차 최적화 시뮬레이터 (Cold Chain Delivery Manager)

> 신선식품처럼 유통기한(TTL)이 있는 물류들의 배송 우선순위가 실시간으로 변하는 상황을 C++ 콘솔 환경에서 구현한 배차 시뮬레이터입니다. 
> 단순히 우선순위가 높은 순서대로 배차하는 것을 넘어서, 제한된 트럭 용량에 맞춰 가장 효율적으로 화물을 싣기 위해 **배낭 알고리즘(Knapsack DP)** 과 **동적 우선순위 시스템**을 적용해봤습니다.

## 핵심 기능 (Key Features)

### 1. TTL 기반 동적 우선순위 시스템
*   콜드체인(신선식품) 화물에 유통기한(TTL) 개념을 넣고, 턴(Tick)이 지날 때마다 TTL이 줄어들도록 구현했습니다.
*   남은 TTL이 임계값(5) 이하로 떨어지면 `10 * 2^(Threshold-TTL)` 공식을 적용해서 우선순위 점수가 급격하게 올라가도록 가중치를 줬습니다.
*   원래는 우선순위가 낮아서 계속 배차에서 밀리던 화물도, 부패하기 직전이 되면 점수가 크게 뛰어 가장 먼저 배차되도록 유도했습니다.

### 2. 배낭 알고리즘(Knapsack DP)을 활용한 다중 배차 최적화
*   트럭의 남은 적재 용량(W)과 화물의 무게, 그리고 변동된 우선순위 점수(V)를 바탕으로 2차원 DP 테이블을 만들었습니다.
*   우선순위가 높은 것부터 무조건 싣는 그리디(Greedy) 방식의 한계를 극복하고, 트럭 용량 안에서 가치(우선순위 점수 합)가 제일 높게 나오는 최적의 조합을 찾습니다.
*   DP 연산이 끝나면 역추적을 통해 실제로 실을 화물을 고르고, 1호차와 2호차에 순서대로 나누어 싣도록 로직을 짰습니다.

### 3. 포인터 스와핑을 통한 정렬 오버헤드 최소화
*   턴마다 대기열을 우선순위 내림차순으로 다시 정렬해야 하는데, 무거운 객체 데이터를 통째로 복사하면 비효율적일 것 같아서 객체를 가리키는 포인터 주소만 서로 바꾸는(Swapping) 방식으로 버블 정렬을 구현해 성능을 높였습니다.

### 4. CSV 파일 입출력을 통한 데이터 저장 및 복구
*   `<fstream>`과 `<sstream>` 라이브러리를 써서 현재 메모리에 있는 객체 정보들을 `.csv` 포맷으로 로컬에 저장(직렬화)합니다.
*   프로그램을 껐다 켜도 CSV 파일을 읽어와서 `stoi`, `stod`로 형변환한 뒤, 동적 배열을 통해 객체 상태를 그대로 복구(역직렬화)할 수 있습니다.

## 클래스 설계 (Class Design)

최대한 객체지향의 단일 책임 원칙(SRP)과 캡슐화를 신경 써서 구조를 분리해 보았습니다.

*   **`Package`**: 개별 화물의 정보(무게, 우선도, 상태, TTL 등)를 가지고 있고, 캡슐화를 위해 Getter와 상태 갱신 함수만 열어둔 순수 데이터 클래스입니다.
*   **`Truck`**: 트럭의 최대 적재 용량을 저장하고, 할당된 `Package` 포인터 배열을 관리합니다.
*   **`DeliveryManager`**: 배낭 알고리즘 연산, 포인터 기반 정렬, 시뮬레이션 턴 진행 등 전체적인 핵심 비즈니스 로직을 굴리는 컨트롤러입니다.
*   **`FileHandler`**: 파일 입출력을 전담해서 CSV로 객체 배열을 저장하고 읽어오는 영속성 관리 클래스입니다.

## 동작 검증 내역

1.  **배차 알고리즘 검증:** 용량이 10.0인 트럭에 단순히 1순위 화물 하나만 싣는 게 아니라, '긴급의약품(무게 6.0/120점) + 고급전자기기(무게 4.0/100점)' 조합을 찾아내서 트럭에 실리는 총 가치(220점)를 최대로 맞추는 것을 확인했습니다.
2.  **동적 가중치 검증:** 처음에는 우선순위가 10점밖에 안 되던 '냉동수산물(P06)'이 턴이 지나면서 TTL이 깎이고 가중치 공식이 적용되면서 90점 이상으로 점수가 폭발해 1순위로 배차되는 것을 확인했습니다.

## Troubleshooting (문제 해결 및 아쉬운 점)

*   **메모리 누수(Memory Leak) 관리:** 
    프로그램이 돌아가는 동안 동적으로 할당되는 화물 객체가 많아서 메모리 누수가 생길 위험이 있었습니다. 이를 막기 위해 `backupForCleanUp`이라는 이중 포인터 배열을 만들어서 로드된 패키지들의 주소를 전부 백업해두고, 시뮬레이션이 끝날 때 루프를 돌면서 한 번에 `delete` 처리하여 메모리를 안전하게 비워줬습니다.
*   **향후 개선 과제:** 
    지금은 화물의 최대 개수(`maxPackages = 20`)를 고정해 놓고 배열을 쓰고 있는데, 나중에는 파일을 읽을 때 먼저 줄 수를 세서 런타임에 배열 크기를 100% 동적 할당하는 가변 크기 컨테이너(Vector 같은 구조)로 리팩토링해보고 싶습니다.
